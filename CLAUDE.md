# MovieApp

UIKit movie app built with Clean Architecture and the VIP (Clean Swift) pattern, using Swift Concurrency throughout.

## Quick Reference

- **Platforms**: iOS / iPadOS 26.5+, visionOS 26.5+
- **Toolchain**: Xcode 26.6, Swift 6 language mode (strict concurrency). Both targets enable the upcoming features `ExistentialAny` and `MemberImportVisibility`
- **Project**: generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`, 2.46.0+) from `project.yml`. `project.pbxproj` and the shared scheme are gitignored; run `./setup.sh` to create them
- **UI**: UIKit only, layout written in code. No SwiftUI, storyboards or xibs
- **Architecture**: Clean Architecture layers, with VIP inside each scene
- **Concurrency**: async/await, actors and `AsyncStream`. The app target's default isolation is `MainActor`, with Approachable Concurrency on
- **Dependencies**: Swift Package Manager only. Current packages: `Networking`, the local package in `Modules/Networking` that wraps Alamofire 5 (networking, behind `IAPIService`; see Networking), Nuke 13 (images, behind `IImageLoader`), `MovieAppDS`, the design system, from the remote `tmdb-movie-ds` package on branch `main`, SimpleKeychain 1 (the session's Keychain item, behind `IKeychainService`; see Auth), and `ArkanaKeys`, generated locally by Arkana (see Secrets). Ask before adding any other third-party package
- **Secrets**: the TMDB read access token lives in `Arkana/.env` as `TmdbReadAccessToken`, which is gitignored (copy `Arkana/.env.example`). [Arkana](https://github.com/rogerluan/arkana) (`gem install arkana`, configured by `Arkana/.arkana.yml`) turns it into the obfuscated local packages in `Arkana/ArkanaKeys/`, also gitignored. Run `./setup.sh` (it calls `./Arkana/sync-keys.sh`) after cloning and whenever `Arkana/.env` changes, or XcodeGen and the build can't find `ArkanaKeys`. `AppConfigs.shared` (`Common/Configuration/`) is the only file that imports `ArkanaKeys`; everything else reads keys from it (`AppConfigs.shared.tmdbReadAccessToken`). Add a property there for each new Arkana secret. Never put the token in source
- **Tests**: Swift Testing unit tests only. No UI test target for now
- **Lint**: SwiftLint (`.swiftlint.yml`) runs in a build phase on every build
- **Style**: [Kodeco Swift Style Guide](https://github.com/kodecocodes/swift-style-guide), with 4-space indentation instead of Kodeco's 2

## Definition of Done

A change is complete only when all of these hold:

1. `swiftlint lint --quiet` reports **zero violations**.
2. The code is written to compile with **zero warnings** under Swift 6 strict concurrency. Check types, isolation and imports by reading the code, not by building.
3. New or changed Domain, Data, Worker, Interactor and Presenter code has unit tests.
4. New files sit in the correct layer folder and follow the naming rules below.
5. The final message tells the user which build or test command to run to verify the change. Don't run it yourself.

## Feature Workflow

1. If `docs/specs/<feature>.md` exists, read it first. Use Plan Mode for work that spans several scenes or layers.
2. Implement from the inside out: Domain (entity, repository protocol), then Data (DTO, then the repository that maps it to Domain), then Scene (VIP, with its Worker), then wire it up in `App/`.
3. Write tests for each layer as you go, then lint. Build and run tests only if the user asks.

## Architecture

### Layers and the Dependency Rule

```
Scenes (VIP) ──► Domain ◄── Data
      ▲                      ▲
      └──────── App ─────────┘   (composition root)
```

Dependencies point **inward only**. Domain knows nothing about the other layers.

- **Domain**: entities and repository protocols (ports). Imports `Foundation` only, never `UIKit`. Contains no DTOs, Alamofire, `URLSession` or persistence details.
- **Data**: implements the Domain repository protocols. Holds persistence and the repositories that map DTOs to Domain entities. Networking and the DTOs (wire types only) live in the `Networking` package (`Modules/Networking`), which only the repositories and `App/` import. DTOs never leave this layer.
- **Scenes**: the presentation layer, built with VIP. Each scene's Worker reaches data through the Domain ports. Scenes depend only on Domain protocols and entities, never on Data types.
- **App**: `AppDelegate`, `SceneDelegate`, `AppDependencies` and the coordinators in `App/Coordinators/`. This is the only place that knows concrete types from every layer and wires them together, and the only place that pushes or presents view controllers.

SOLID in practice:

- One reason to change per type.
- Small role protocols (`IMovieListInteractor`), not large ones.
- Depend on protocols and inject them through `init`.
- No singletons, no service locators, no global mutable state. The one exception is `AppConfigs.shared` (build-time keys). `AppDependencies` creates the one `APIService` (the one network session) and injects it into the repositories. The only other session is the test-only `CallbackAPIService` (see Networking).

### VIP Scene

```
ViewController ──Request──► Interactor ──Response──► Presenter ──ViewData──► ViewController
      │                          ▲
      │                          │ async
      │                        Worker ──► Domain ports (repositories)
      │
      └──routeTo…(movie:)──► Router ──closure──► Coordinator (App/Coordinators)
```

| Component | Protocol(s) | Responsibility | Never |
|---|---|---|---|
| ViewController | `I<Scene>ViewController` | Builds views, sends user events as a `Request`, renders the `ViewData`, and passes a route's data to the Router | Business logic, formatting, calling the Worker |
| Interactor | `I<Scene>Interactor` | Business rules, scene state, calling its Worker, emitting a `Response` | Importing UIKit, formatting for display, calling repositories directly |
| Worker | `I<Scene>Worker` | The scene's data access: calls the Domain ports and combines their results (for example, merging watch progress with movie details) | Importing UIKit, holding scene state, formatting for display |
| Presenter | `I<Scene>Presenter` | Turns a `Response` into a `ViewData`: localized text, formatted dates and numbers | Importing UIKit, holding state, calling the Worker |
| Router | `I<Scene>Router` | Takes the route's data as a parameter (`routeToMovieDetail(movie:)`) and calls the closures its coordinator passed in through the factory | Depending on the Interactor, touching a navigation controller, building scenes, business logic |
| SceneFactory | none | Builds the scene, including its Worker from the ports it's given, and wires its components | Any other work |
| Models | none | `enum <Scene>Model` namespace, with `Request` / `Response` / `ViewData` for each scene use case | Behavior |

Rules:

- **Ownership**: the ViewController holds the Interactor and Router strongly. The Interactor holds the Presenter and the Worker strongly. The Presenter holds the ViewController `weak`. The Router holds only the coordinator's closures, which capture the coordinator `[weak self]`.
- Inject every dependency through `init` into a `private let`. Never use `var interactor: IMovieListInteractor!`.
- Each scene use case (one `Request` / `Response` / `ViewData` triple) gets one method on each boundary: `loadMovies(request:)` → `presentMovies(response:)` → `displayMovies(viewData:)`. The Worker's methods are named for the data they fetch (`fetchPopularMovies(page:)`).
- **Shared-Response variant**: an action whose only visible result is the screen's state can skip its own `Response` / `ViewData` and redraw through the screen's load use case. Profile's `changeAppearance(request:)`, `signIn(request:)` and `signOut(request:)` have a `Request` only, and every change reaches the screen through `presentProfile(response:)`.
- **Scene with no use case**: a screen that loads nothing and has no business rules, such as Welcome, has only Models (its `DisplayedContent`), ViewController, Router, SceneFactory and Views. The ViewController builds the display strings, and every user action goes to the Router.
- Name types `<Scene><Role>`. Put one type per file, with the type's boundary protocol in the same file. The models namespace is `enum <Scene>Model` in `<Scene>Models.swift`, and what the Presenter hands the ViewController is a `ViewData`, passed as `display…(viewData:)`.
- Name each boundary protocol `I` plus the type that implements it: `I<Scene>Interactor`, `I<Scene>Presenter`, `I<Scene>ViewController`, `I<Scene>Worker` and `I<Scene>Router`. The `MARK` above a conformance uses the same name (`// MARK: - IMovieListInteractor`). The `I` prefix is only for scene protocols, repository ports (`IMovieRepository`, implemented by `MovieRepository`), the `IWebAuthenticator` port and service protocols: `IAPIService` / `ICallbackAPIService` (see Networking), `IKeychainService`, `ISessionService` and `IImageLoader`. Other protocols keep role names (`ImageURLProvider`, `Coordinator`). A protocol that supplies something is named `<Thing>Provider` (`ImageURLProvider`, `ZoomTransitionSourceProvider`), never `<Thing>Providing`; only Apple's own protocols (`ASWebAuthenticationPresentationContextProviding`) keep that suffix.
- **Workers are `nonisolated` and `Sendable`**: `nonisolated protocol I<Scene>Worker: Sendable` and `nonisolated struct <Scene>Worker`, with the conformance in a `nonisolated extension`. Interactors call them from child tasks (`async let`), and a nonisolated async method still runs on the Interactor's main actor when called directly. One Worker per scene; two scenes that need the same port each call it, and shared behavior such as caching belongs in a repository decorator.
- Scenes never reach each other. The ViewController passes the data a route needs to its Router as a parameter, and the Router hands it to a coordinator closure (`onSelectMovie(Movie)`); the coordinator builds and shows the next scene. There is no data store, and a Router never depends on the Interactor. This keeps routers free of UIKit and state, and testable with a closure spy.
- **Route data travels in the `ViewData`**: a displayed item the user can open carries the Domain entity its route needs (`let movie: Movie`, with `id` computed from it), so the ViewController can pass it on without asking the Interactor. Tapping, and anything else that only navigates, is not an Interactor use case.

```swift
final class MovieListInteractor {
    private let presenter: any IMovieListPresenter
    private let worker: any IMovieListWorker

    init(presenter: any IMovieListPresenter, worker: any IMovieListWorker) {
        self.presenter = presenter
        self.worker = worker
    }
}

// MARK: - IMovieListInteractor
extension MovieListInteractor: IMovieListInteractor {
    func loadMovies(request: MovieListModel.LoadMovies.Request) async {
        do {
            let movies = try await worker.fetchPopularMovies(page: 1)
            presenter.presentMovies(response: MovieListModel.LoadMovies.Response(result: .success(movies)))
        } catch is CancellationError {
            return
        } catch {
            presenter.presentMovies(response: MovieListModel.LoadMovies.Response(result: .failure(error)))
        }
    }
}
```

```swift
import Foundation

protocol IMovieListPresenter {
    func presentMovies(response: MovieListModel.LoadMovies.Response)
}

final class MovieListPresenter {
    weak var viewController: (any IMovieListViewController)?
}

// MARK: - IMovieListPresenter
extension MovieListPresenter: IMovieListPresenter {
    func presentMovies(response: MovieListModel.LoadMovies.Response) {
        switch response.result {
        case .success(let movies) where movies.isEmpty:
            viewController?.displayMovies(viewData: .empty(message: String(localized: "No movies yet")))
        case .success(let movies):
            viewController?.displayMovies(viewData: .content(movies.map(makeDisplayedMovie(from:))))
        case .failure:
            viewController?.displayMovies(viewData: .failure(message: String(localized: "Unable to load movies")))
        }
    }
}

private extension MovieListPresenter {
    func makeDisplayedMovie(from movie: Movie) -> MovieListModel.DisplayedMovie {
        MovieListModel.DisplayedMovie(
            movie: movie,
            title: movie.title,
            releaseYear: movie.releaseDate?.formatted(.dateTime.year()) ?? "-"
        )
    }
}
```

```swift
protocol IMovieListViewController: AnyObject {
    func displayMovies(viewData: MovieListModel.LoadMovies.ViewData)

final class MovieListViewController: UIViewController {
    private let interactor: any IMovieListInteractor
    private let router: any IMovieListRouter
    private var loadTask: Task<Void, Never>?

    private lazy var collectionView = makeCollectionView()
    private lazy var dataSource = makeDataSource()

    init(interactor: any IMovieListInteractor, router: any IMovieListRouter) {
        self.interactor = interactor
        self.router = router
        super.init(nibName: nil, bundle: nil)
    }

    required init?(coder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }

    isolated deinit {
        loadTask?.cancel()
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        title = String(localized: "Movies")
        setUpLayout()
        loadMovies()
    }

    private func loadMovies() {
        loadTask?.cancel()
        loadTask = Task { [interactor] in
            await interactor.loadMovies(request: MovieListModel.LoadMovies.Request())
        }
    }
}

// MARK: - IMovieListViewController
extension MovieListViewController: IMovieListViewController {
    func displayMovies(viewData: MovieListModel.LoadMovies.ViewData) {
        switch viewData {
        case .content(let movies):
            contentUnavailableConfiguration = nil
            var snapshot = NSDiffableDataSourceSnapshot<Int, MovieListModel.DisplayedMovie>()
            snapshot.appendSections([0])
            snapshot.appendItems(movies)
            dataSource.apply(snapshot)
        case .empty(let message), .failure(let message):
            var configuration = UIContentUnavailableConfiguration.empty()
            configuration.text = message
            contentUnavailableConfiguration = configuration
        }
    }
}

// MARK: - UICollectionViewDelegate
extension MovieListViewController: UICollectionViewDelegate {
    func collectionView(_ collectionView: UICollectionView, didSelectItemAt indexPath: IndexPath) {
        guard let movie = dataSource.itemIdentifier(for: indexPath)?.movie else { return }
        router.routeToMovieDetail(movie: movie)
    }
}
```

`AppDependencies` in `App/` owns long-lived services (`APIService`, which owns the Alamofire `Session`, the Nuke `ImagePipeline`, repositories). It conforms to one `<Scene>Factory` protocol per scene, one extension each, and every `make<Scene>()` calls that scene's `<Scene>SceneFactory`. The two names are different layers: a `<Scene>Factory` protocol (`HomeFactory`) is what a coordinator asks for, and the `<Scene>SceneFactory` enum (`HomeSceneFactory`) wires the VIP components. Coordinators use `AppDependencies` as a factory, but it is one container: every scene shares its instances and the app creates exactly one, so keep the `AppDependencies` name and the `make` prefix. A factory with more than five inputs takes a nested `Dependencies` struct, which keeps it under SwiftLint's parameter limit.

### Coordinators

Coordinators in `App/Coordinators/` own all navigation.

- `AppCoordinator` puts `MainTabCoordinator`'s tab bar controller in the window.
- `MainTabCoordinator` builds three `UITab`s (Home, Saved, Profile) and a `UISearchTab`, whose root is the Search scene (the requirement's Discover area).
- Each tab coordinator owns its `UINavigationController`. It builds scenes and passes the routing closures, capturing itself `[weak self]`.
- **Coordinators never see `AppDependencies`.** Each one declares `typealias Dependencies` as the `<Scene>Factory` protocols it needs (`HomeFactory & MovieDetailFactory`) and stores `any Dependencies`. A protocol lives in the file of the coordinator (or `MovieDetailFlow`) that uses it. A parent's alias combines its children's (`HomeCoordinator.Dependencies & SearchCoordinator.Dependencies & …`). A new scene means a new protocol, a conformance on `AppDependencies`, and a conformance on `SceneFactorySpy`, which stands in for it in coordinator tests.
- `SearchCoordinator` pushes Genre Movies when a genre is tapped, and its lazy `MovieDetailFlow` pushes Movie Detail from a poster with `.push`.
- `MovieDetailFlow` pushes Movie Detail on its tab's stack. A `.zoom` transition starts from the view the source screen returns through `ZoomTransitionSourceProvider`, and is skipped under Reduce Motion.
- `ProfileCoordinator` presents Welcome as a page sheet when Profile's sign-in row is tapped, and ignores the request while something is already presented. It also presents the sign-out confirmation alert. Welcome's sign-in action awaits Welcome's dismissal (`withCheckedContinuation` over `dismiss(animated:completion:)`), then calls Profile's own `signIn()`, so the approval sheet never presents over a closing sheet.
- The tab bar stays visible on pushed screens (`hidesBottomBarWhenPushed` stays `false`). Only full-screen modals cover it.

### Images (Nuke)

- Import Nuke only in `Common/Images/` and `App/`.
- `AppDependencies` builds one `ImagePipeline` with its own `ImageCache` and a 150 MB `DataCache`. Never use `ImagePipeline.shared` or `ImageCache.shared`.
- Presenters turn an `ImagePath` into a URL through `ImageURLProvider` and hand cells a `DisplayedArtwork`. `ArtworkView` loads it through `IImageLoader`, downsampled to the view's size, and shows a generated placeholder until then.

### Domain and Data Shape

```swift
nonisolated struct Movie: Identifiable, Hashable, Sendable {
    let id: Int
    let title: String
    let releaseDate: Date?
}

nonisolated protocol IMovieRepository: Sendable {
    func popularMovies(page: Int) async throws -> [Movie]
}
```

Domain holds only entities and ports. The code that calls ports for a screen, and combines their results, lives in that scene's Worker (see the reference scene).

A Worker, and the scene factory that builds it, depends on whole repository ports: `let savedMoviesRepository: any ISavedMoviesRepository`, never a role protocol carved out of one (`any SavedMoviesObserving`). Every data dependency then reads as the `I`-prefixed port it is, even when the Worker calls only one of its members.

### Networking (Alamofire)

The network layer is the `Networking` module, a local Swift package in `Modules/Networking`. `APIService` wraps Alamofire, and repositories reach it only through the `IAPIService` protocol. Every TMDB endpoint is a case of one enum, `TMDBEndpoint` in `Sources/Networking/Endpoints/TMDBEndpoint.swift`. Each endpoint's wire types live in one DTO file under `Sources/Networking/DTOs/`. The module knows no Domain types: repositories in `MovieApp/Data/Repositories/` map its DTOs to Domain entities.

#### Client

- **Confine Alamofire** to the `Networking` module and its tests. Only `Data/Repositories/` and `App/` `import Networking` (lint rule `no_networking_outside_data`). Repositories take `any IAPIService` through `init` and use `TMDBEndpoint`, the DTOs and `NetworkError`. They never see `APIService` or a `Session`.
- **One shared client**: `AppDependencies` creates the app's only `APIService` with `APIService(readAccessToken: AppConfigs.shared.tmdbReadAccessToken)`, which builds the `Session` and its `ReadAccessTokenInterceptor` inside the module, and passes it to every repository's `init`. Tests build their own client with `APIService.makeStub()`. The one other client is the test-only `CallbackAPIService` below. Never use `AF` or `Session.default`.
- **Public API**: mark `public` only what the app uses: `IAPIService`, `APIService` and `init(readAccessToken:userAccessToken:)`, `ICallbackAPIService`, `CallbackAPIService` and `init(readAccessToken:)`, `APIRequestHandle` and `cancel()`, `NetworkError`, `TMDBEndpoint` and `asURLRequest()`, and every DTO type, typealias and stored property (public enum cases need public associated types). Everything that takes an Alamofire type stays internal (`APIService.init(configuration:interceptor:userAccessTokenInterceptor:)`, `APIService.requestInterceptor(for:)`, `CallbackAPIService.init(configuration:interceptor:)`, `NetworkError.init(_:)`, the interceptors), and so do `method`, `path`, `parameters`, `body`, `authorization` and `carriesCredentials`. A `Parameters` or `Request` that a repository builds gets an explicit `public init` that mirrors the memberwise one (same labels, order and defaults). Tests reach internals with `@testable import Networking`.
- **Calling an endpoint**: `let page: SearchMoviesDTO.Response = try await apiService.request(.searchMovies(parameters: .init(query: query)))`, then map it to Domain entities in the repository (see DTOs > Mapping).
- **Async API only**: use `serializingDecodable(_:decoder:)` with `.response`, `.result` or `.value`. Never use the `response…` completion-handler methods. Always call `.validate()` so non-2xx statuses fail.
- **Callback client (test-only)**: `CallbackAPIService` (`ICallbackAPIService`) is the one exception to async-only. It mirrors `APIService` on `responseDecodable(of:decoder:completionHandler:)`, delivers `Result<Response, any Error>` (failing with `NetworkError` or `CancellationError`) on the main queue, and returns an `APIRequestHandle` to cancel. It exists to compare a callback chain with the async one, through `CallbackGenreRepository`, `SearchCallbackWorker` and `SearchInteractor.loadGenresUsingCallback`. `AppDependencies` builds that chain (its own `CallbackAPIService`, so a second `Session`) because `SearchInteractor` requires a callback Worker, but no screen calls `loadGenresUsingCallback`. Don't route other repositories through it.
- **Decoding is already off the main actor**: Alamofire decodes on its serialization queue, so `APIService` needs no `@concurrent` decode step.
- **Cancellation**: `serializingDecodable` cancels the request when the calling `Task` is cancelled (`automaticallyCancelling` defaults to `true`). It reports this as `AFError.explicitlyCancelled`, so `APIService` rethrows it as `CancellationError` and the Interactor's `catch is CancellationError` keeps working.
- **Errors**: `AFError` never leaves `APIService`. Map it to `NetworkError`.
- **Debug logging**: in Debug builds `APIService` and `CallbackAPIService` log, through the shared internal `APIResponseLogger`, each request and response (method, URL, status, headers, body) through `os.Logger`, category `network`, with the `Authorization` header redacted. Keep that redaction for any header you start logging. Endpoints whose `TMDBEndpoint.carriesCredentials` is `true` (the auth and session calls, `accountDetails` and the v3 writes) log one line instead, with method, path and status only: no query string, headers or body. `carriesCredentials` switches over every case with no `default`, and a new endpoint that carries a token or a session ID must return `true`.

```swift
public nonisolated final class APIService: Sendable {

    private let decoder: JSONDecoder
    private let responseLogger = APIResponseLogger()
    private let userAccessTokenInterceptor: UserAccessTokenInterceptor?

    public convenience init(readAccessToken: String, userAccessToken: @escaping @Sendable () -> String? = { nil }) {
        self.init(
            interceptor: ReadAccessTokenInterceptor(token: readAccessToken),
            userAccessTokenInterceptor: UserAccessTokenInterceptor(accessToken: userAccessToken)
        )
    }

    init(
        configuration: URLSessionConfiguration = .af.default,
        interceptor: (any RequestInterceptor)? = nil,
        userAccessTokenInterceptor: UserAccessTokenInterceptor? = nil
    ) {
        session = Session(configuration: configuration, interceptor: interceptor)
        self.userAccessTokenInterceptor = userAccessTokenInterceptor
        let decoder = JSONDecoder()
        decoder.keyDecodingStrategy = .convertFromSnakeCase
        self.decoder = decoder
    }
}

// MARK: - IAPIService
nonisolated extension APIService: IAPIService {
    public func request<Response: Decodable & Sendable>(_ endpoint: TMDBEndpoint) async throws -> Response {
        let response = await session.request(endpoint, interceptor: requestInterceptor(for: endpoint))
            .validate()
            .serializingDecodable(Response.self, decoder: decoder)
            .response
        responseLogger.log(response, for: endpoint)

        switch response.result {
        case .success(let value):
            return value
        case .failure(let error) where error.isExplicitlyCancelledError:
            throw CancellationError()
        case .failure(let error):
            throw NetworkError(error)
        }
    }
}

nonisolated extension APIService {
    func requestInterceptor(for endpoint: TMDBEndpoint) -> UserAccessTokenInterceptor? {
        switch endpoint.authorization {
        case .readAccessToken:
            nil
        case .userAccessToken:
            userAccessTokenInterceptor
        }
    }
}
```

#### Endpoint Enum

- **One case per endpoint**. Path IDs are labeled associated values (`movieID:`, `accountObjectID:`). Query parameters come as `parameters: <Name>DTO.Parameters` and a JSON body as `request: <Name>DTO.Request`.
- **Exhaustive switches**: `method`, `path`, `parameters`, `body` and `authorization` switch over every case with no `default`, so a new case doesn't compile until each property handles it.
- **Encoding**: `asURLRequest()` always encodes `parameters` into the query string and `body` as JSON, so one request can carry both (e.g. `session_id` in the query and a JSON body). Both encoders use `.convertToSnakeCase`. The query encoder sends booleans as `true`/`false` (Alamofire's default is `1`/`0`).
- **No redundant endpoints**. Before adding a case, check whether one of these already covers it:
  - `append_to_response` on `movieDetails` or `personDetails`. Credits, videos, images, reviews, release dates, watch providers, recommendations and account states all come back that way.
  - An existing case with a category enum, e.g. `movieList(category:)` for now playing, popular, top rated and upcoming.
- **Adding an endpoint**:
  1. Create `Modules/Networking/Sources/Networking/DTOs/<Group>/<Name>DTO.swift`, with its types, typealiases and stored properties `public`. Give a `Parameters` or `Request` an explicit `public init` that mirrors the memberwise one once a repository builds it.
  2. Add the case and handle it in every switch.
  3. Add a row to `TMDBEndpointExpectation.all` in `TMDBEndpointTests` (`NetworkingTests/Endpoints/`).
  4. Add a decoding test if the DTO has custom coding keys or an `init(from:)`.

```swift
        case .addFavorite:

        }

        case .movieDetails(_, let parameters):
            parameters
        case .addFavorite(_, let parameters, _):
            parameters
        }
    }

    var body: (any Encodable & Sendable)? {
        switch self {
        case .movieDetails:
            nil
        case .addFavorite(_, _, let request):
            request
        }
    }
```

#### DTOs

- **One file per endpoint**: an `enum <Name>DTO` namespace holding up to three types. Leave out the ones the endpoint doesn't use:
  - `Parameters` (`Encodable`): the query string.
  - `Request` (`Encodable`): the JSON body.
  - `Response` (`Decodable`).
- **Shared shapes** live in `Sources/Networking/DTOs/Shared/` and are reused through `typealias`: `PageDTO<MovieSummaryDTO>`, `StatusDTO`, `SessionParametersDTO`, `GenreDTO`, `ImageDTO`.
- **Isolation**: declare the namespace `public nonisolated enum <Name>DTO`, so every type nested in its body inherits `nonisolated`. Types declared in an extension of the namespace need `nonisolated extension <Name>DTO`. Mark every DTO type `Sendable`.
- **Keys**: properties are camelCase. Encoders use `.convertToSnakeCase` and `APIService`'s decoder uses `.convertFromSnakeCase`. Write a `CodingKeys` raw value only where the conversion can't produce the name:
  - **Acronyms when decoding**: `imdb_id` becomes `imdbId`, so write `case imdbID = "imdbId"`. Encoding needs nothing: `sessionID` already becomes `session_id`.
  - **ISO codes**: `case languageCode = "iso6391"` and `case countryCode = "iso31661"`.
  - **Dotted and slashed keys**: `"vote_count.gte"`, `"watch/providers"`.
- **Parameter values**:
  - Optional parameters are `var` optionals, so `nil` leaves the key out.
  - Booleans are non-optional (`var includeAdult = false`), because lint's `discouraged_optional_boolean` flags `Bool?`.
  - Comma-joined values such as `append_to_response` are typed enum arrays, joined in a custom `encode(to:)`.
- **Flattened JSON**: when extra fields sit next to movie fields in the same object (rated movies, person credits), decode `MovieSummaryDTO(from: decoder)` and then read the extra keys from the same decoder.
- **Mapping**: DTOs hold no conversion code: no `toDomain()`, no extensions that build Domain entities. The repository maps the response right after the request, as `GenreRepository` does: `response.genres.map { Genre(id: $0.id, name: $0.name) }`. A conversion that is longer than a line, or that several methods share (`MovieSummaryDTO` to `Movie`, `PageDTO` to `Page`), goes in the repository's `private extension` as `make<Entity>(from:)`. Repository tests cover it through `APIServiceStub`.

#### Auth

- **Sign-in uses v4**:
  1. `createRequestToken`.
  2. The user approves at `https://www.themoviedb.org/auth/access?request_token=…`. This is a web page, not an API endpoint.
  3. `createAccessToken` returns the user access token and the `accountObjectID` used in `/4/account/…` paths.
- **Writes are v3**: v4 has no favorite, watchlist or rating endpoints. Those take a `session_id` from `createSessionFromAccessToken`.
- **Sign-out** calls both `deleteAccessToken` and `deleteSession`.
- **Tokens**: `TMDBEndpoint.authorization` says which bearer token a request needs:
  - `.userAccessToken` for the v4 account lists.
  - `.readAccessToken`, the app's API read token, for everything else, including the v4 auth calls and the v3 writes.
- **Attaching the token**: do it in a `RequestInterceptor` in the `Networking` module (`Sources/Networking/Client/`), never by setting the header by hand. Pass the read-token interceptor to `Session(interceptor:)`. `APIService` takes a `userAccessToken` reader closure (`init(readAccessToken:userAccessToken:)`, which defaults to `{ nil }`), and `requestInterceptor(for:)` passes a `UserAccessTokenInterceptor` per request (`session.request(endpoint, interceptor:)`) when `endpoint.authorization == .userAccessToken`. Alamofire runs the session's interceptor first and the request's second, and `HTTPHeaders.add` replaces the header, so the user token wins. The reader is called at send time; when it returns `nil`, the read token stays and TMDB answers 401.
- **Session owner**: `AuthRepository` (an actor in `Data/Repositories/`) is the only writer of the Keychain item, through `CredentialRepository`. It writes the Keychain first and changes its phase second, in both directions, so a failed save never shows a signed-in state. `APIService`'s token reader only reads it. `IAuthRepository` exposes no token.
- **Observing**: screens read the auth state through their Worker from `IAuthRepository.changes`, which yields the current state first. Only Profile starts a sign-in, so `AuthState` has no pending case; Profile shows its own pending row.
- **Account refresh**: Profile refreshes the signed-in account once per launch through `IAuthRepository.refreshAccount()`, which fetches `accountDetails` for the stored session (`SessionService.fetchAccount(for:)`), saves the new name, username and avatar path, then broadcasts. A 401 there means TMDB rejected the session: `AuthRepository` signs out locally with no revoke call (and stays signed in if the Keychain delete fails), and returns `.sessionEnded` so Profile can say why. Any other failure returns `.unchanged`. `AuthSession` fields added later must be optional, so sessions saved by earlier versions still decode.
- **Web sheet**: `WebAuthenticator` (`Common/Authentication/`) opens the approval page in an ephemeral `ASWebAuthenticationSession` with the `movieapp` callback scheme. Info.plist registers no URL type, so only that sheet receives the callback. It presents over the scene's window, so `SceneDelegate` creates the window first and builds `AppDependencies(window:)`.
- **Callback exception**: Alamofire's interceptor API is callback-based. Implementing it is one of the two allowed exceptions (see Concurrency) to the no-completion-handler rule.

## Concurrency

- Swift 6 strict concurrency is on. Fix every diagnostic properly. Never silence one with `@unchecked Sendable`, `nonisolated(unsafe)` or `@preconcurrency` unless the user approves and a comment explains why.
- The app target sets `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and `SWIFT_APPROACHABLE_CONCURRENCY = YES`. This has several consequences:
  - Scene types are implicitly `@MainActor`. Don't add the annotation again.
  - **Declare every top-level Domain and Data type `nonisolated`**: entities, DTOs and DTO namespaces, repository protocols, and their implementations. Scene Workers follow the same rule (see VIP Scene). Make them `Sendable` as well. Otherwise their `Decodable`, `Hashable` and similar conformances become main-actor-isolated and fail off the main actor. The `Networking` package has no default isolation, so there the keyword is redundant; keep writing it so the code reads the same in both places.
  - **Nested types inherit, extensions don't**:
    - A type declared inside another type's body takes the enclosing type's isolation. Inside a `nonisolated` type it needs no annotation. Inside a main-actor type, such as a scene's `enum MovieListModel`, it is `@MainActor` unless marked `nonisolated`, like `MovieListModel.DisplayedMovie`.
    - An extension does not inherit. Its members, the types declared in it and the conformances it adds all default to `@MainActor`, even on a `nonisolated` type. Write `nonisolated extension` for extensions of Domain and Data types.
  - **Why this is easy to miss**: the compiler reports it only where nonisolated code uses the member or conformance directly (`conformance of ... crosses into main actor-isolated code`, `main actor-isolated conformance ... cannot be used in nonisolated context`). It stays silent when the only use is inside compiler-synthesized `Codable` code, or inside `try await`, where the `await` quietly hops to the main actor.
  - **Diffable data source identifiers must be `nonisolated` + `Hashable` + `Sendable`**, like `MovieListModel.DisplayedMovie`. Without that you get the compile error `main actor-isolated conformance ... cannot satisfy conformance requirement for a 'Sendable' type parameter`.
  - A `nonisolated async` function runs on the caller's actor. Put CPU-heavy work (image processing, decoding outside `APIService`) in `@concurrent` functions so it leaves the main actor.
- Use async/await everywhere:
  - No completion handlers, GCD (`DispatchQueue`), Combine or `OperationQueue`. The exceptions are implementing Alamofire's `RequestInterceptor` and the test-only callback chain for Search genres (`CallbackAPIService` → `CallbackGenreRepository` → `SearchCallbackWorker`, bridged once with `withCheckedThrowingContinuation` in `SearchInteractor.loadGenresUsingCallback`), which `AppDependencies` builds but no screen calls.
  - Use Alamofire's async API (`serializingDecodable`), not its `response…` handlers.
  - Bridge other callback APIs with `withCheckedThrowingContinuation`.
  - Use `AsyncStream` / `AsyncSequence` for streams of values.
- Use an `actor` for shared mutable state that lives off the main actor, such as caches.
- The ViewController owns each `Task` it starts. Store the task, cancel it in `isolated deinit` or when its work becomes irrelevant, and capture dependencies (`[interactor]`) rather than `self`. Avoid `Task.detached`.
- `I<Scene>Interactor` methods that do work are `async` so tests can `await` them directly. `I<Scene>Presenter` and `I<Scene>ViewController` methods are synchronous.
- Treat `CancellationError` as a normal outcome. Never present it as a failure.
- The test targets have no default isolation. Mark suites and test doubles that touch scene types `@MainActor`.

## Code Style (Kodeco)

SwiftLint enforces most of these rules. You are responsible for the rest.

- **Spacing**:
  - Indent with 4 spaces, never tabs. This overrides Kodeco's 2-space rule.
  - Lines warn at 120 characters and error at 160.
  - Open braces on the same line.
  - Leave one blank line between methods, none after `{` or before `}`, and never more than one in a row.
- **Naming**:
  - Prefer clarity over brevity, and don't abbreviate.
  - Use `UpperCamelCase` for types and `lowerCamelCase` for everything else.
  - Keep acronyms in uniform case (`movieID`, `urlString`).
  - Booleans read as assertions (`isLoading`, `hasNextPage`).
  - Types and protocols are role nouns: no `Manager` types and no `-ing` protocol names (`IImageLoader`, not `ImageLoading`).
  - Factory methods start with `make`.
  - Scene boundary protocols, repository ports (`IMovieRepository`), `IWebAuthenticator` and service protocols (`IAPIService`, `ICallbackAPIService`, `IKeychainService`, `ISessionService`, `IImageLoader`) take an `I` prefix. This is a project rule; see VIP Scene.
  - Delegate methods take the source object as an unnamed first parameter.
  - Use US English.
- **Organization**:
  - Order members as properties, `init`, lifecycle, then methods.
  - Put each protocol conformance in its own extension under `// MARK: - <Protocol>`.
  - Declare a protocol at the top of its implementation's file (`IKeychainService` in `KeychainService.swift`). Domain ports stay in `Domain/Repositories/`, and a protocol with several implementations (`Coordinator`, `ZoomTransitionSourceProvider`) keeps its own file.
  - Put helpers in a `private extension`.
  - Delete unused code and template leftovers.
  - Import only what you use, sorted.
- **Classes**: mark every class `final` unless it is designed for inheritance. Use a `struct` for values and a `class` for identity or lifecycle.
- **Access control**: default to `private`. Use `fileprivate` only when the compiler needs it. Never write `internal`. Inside `Networking`, mark `public` only what the app uses (see Networking > Public API).
- **`self`**: omit it unless the compiler requires it.
- **Types**:
  - Let the compiler infer types. Annotate empty collections (`var movies: [Movie] = []`).
  - Use shorthand syntax (`[String]`, `Int?`).
  - Write `any` on every existential (`any ISearchPresenter`, `any Error`, `(any IHomeViewController)?`). Both targets set `SWIFT_UPCOMING_FEATURE_EXISTENTIAL_ANY = YES`, so a bare protocol type is a compile error. Use `some` or a generic instead when the concrete type is fixed and dispatch cost matters.
  - Prefer `let` over `var`.
  - New code has no `static` members. Constants are instance `private let`s (`private let key = "tmdb-session"`, as in `AppearanceRepository`), and test values are instance properties of the suite. Existing statics stay until their file is reworked.
- **Golden path**:
  - Exit early with `guard` instead of nesting conditions.
  - A `guard` `else` block only exits (return, throw, break, continue, `fatalError`).
  - Use `if let value` / `guard let value` shorthand.
- **Optionals**:
  - No force unwrap, force cast, force try, or implicitly unwrapped optionals. Lint reports an error for each.
  - In tests, use `#require`.
- **Closures**:
  - Use a trailing closure only when a single closure is the last argument.
  - Give closure parameters descriptive names.
  - Use implicit returns in single-expression closures and getters.
- **Memory**:
  - Capture `[weak self]`, then `guard let self else { return }`. Never capture `unowned`.
  - Mark delegates `weak`.
- **Minor**:
  - Omit `get` on read-only computed properties.
  - No semicolons, no parentheses around conditions, and no emoji in code.
  - Open a multi-line string with `"""` on the assignment line.
- **Logging**: use `os.Logger`. `print` produces a lint warning.

  - **ViewController** (for logic that matters): add an `InteractorSpy` and a `RouterSpy`, and assert on the requests and routes that user events trigger.
- **Coordinators**: inject `SceneFactorySpy`, call the routing closure it captured, and assert on the root view controller and the scenes requested. Keep the coordinator in a stored property of the suite: its closures capture it `[weak self]`, and a local constant can be released before the closure runs.
- Name test doubles after their protocol, dropping the `I`: `<Name>Spy` records calls and `<Name>Stub` returns canned results (`MovieListPresenterSpy` for `IMovieListPresenter`, `MovieListWorkerStub` for `IMovieListWorker`, `MovieRepositoryStub` for `IMovieRepository`, `SavedMoviesRepositoryStub` for `ISavedMoviesRepository`). Keep them `private` to the test file. Shared ones go in `MovieAppTests/Stubs/`.
- **Shared stubs are configured, not edited**: they take a `Result` per method, defaulting to success (`MovieRepositoryStub(trending: .failure(StubError.failed))`), so a new scenario, including an error path, needs no change to the stub. A repository stub conforms to the whole port: reads answer from its canned data, and members no SUT should call (writes, `isPersistent`) call `Issue.record("Unexpected call to save(_:)")`, so an unexpected call fails the test instead of passing silently.
- **Hold the SUT through its boundary protocol** (`let sut: any ISearchInteractor = SearchInteractor(...)`, `makeSUT() -> any IHomeWorker`), so a test can only use the contract callers use. This matters most where an implementation narrows the protocol: `SavedMoviesRepository` drops `throws`, so only a test through `any ISavedMoviesRepository` checks the contract Workers rely on. A Presenter is wired in the suite's `init` (`let presenter = SearchPresenter()`, set `viewController`, then `sut = presenter`). Keep the concrete type where there is no protocol to test through: coordinators (tests read `navigationController`), `AsyncBroadcaster`, DTOs, `TMDBEndpoint` and entities.
- Test names describe behavior: `loadMoviesPresentsFetchedMovies()`. Each test checks one behavior; when its asserts cover several, split it.
- **Given / When / Assert**: split each test body into blocks separated by one blank line, and open each block with its marker comment and nothing else:
  - `// Given`: inputs, stubs and the system under test.
  - `// When`: the one call under test.
  - `// Assert`: the checks.
  - Leave out a marker whose block would be empty. A suite whose `init` already builds the SUT starts at `// When`, and a test that only reads a computed property of a value built in Given has no `// When`.
  - When the call has to sit inside `#expect(throws:)`, mark that block `// When & Assert`.
- `await` async business methods directly. No sleeps and no `XCTestExpectation` for async/await code.
- Unit tests never touch the network.
  - **Repositories**: inject `APIServiceStub(endpoint:result:)` from `MovieAppTests/Stubs/`. It decodes the canned JSON with `TMDBJSON`, so the real DTOs and mappings run. It first builds both requests and fails the test through `#require` unless the method, URL and body the repository sent match the endpoint it was given, so repository tests check both the request the repository builds from its inputs and the mapping; `TMDBEndpointTests` covers how each endpoint encodes. Build it in each test's `// Given`. A caller that sends several requests gets a `private` multi-response stub in its own test file.
  - **`APIService`**: build the client with `APIService.makeStub()` (in `NetworkingTests/Stubs/`), a real `Session` whose requests `URLProtocolStub` answers. Never build that `Session` by hand. `URLProtocolStub` keys responses by URL in shared static state and tests run in parallel, so each test must stub a URL no other test uses (for example, its own page number: `APIServiceTests` use Popular pages 1–5, `CallbackAPIServiceTests` 101–105). An unstubbed URL fails like a lost connection, and `.noResponse` keeps a request in flight until it's cancelled.
  - **Interceptors**: call `adapt(_:for:completion:)` directly and assert on the adapted `URLRequest`.
- `TMDBEndpointTests` checks every endpoint's method, URL and body through one parameterized table, `TMDBEndpointExpectation.all`. Add a row for each new case.
- Repository tests read each canned response from `MovieAppTests/Fixtures/JSON/<name>.json` through `JSONFixture.named(_:)`, which takes a `JSONFixture.JSONFiles` case (add one per file). One file per response shape, holding only the required fields and the ones a test asserts. Synchronized folders copy resources to the bundle root, so file names must be unique across the test target. An inline JSON string is fine for a one-off edge case. `TMDBJSON.decode(_:from:)` decodes either with the same `.convertFromSnakeCase` strategy as `APIService`. Each test target has its own five-line copy of it; keep both on that strategy.
- The project has no UI test target for now. Don't add one, or any UI tests, unless the user asks.

## Do Not

- Build, test or run the project unless the user explicitly asks.
- Use SwiftUI, Combine, GCD, storyboards, xibs or Interface Builder outlets.
- Force unwrap, force cast, force try, or declare implicitly unwrapped optionals.
- Put business logic in a ViewController, import UIKit in Domain, an Interactor or a Presenter, or let DTOs leave the Data layer.
- Create singletons or global mutable state, or reach across scenes directly.
- Silence concurrency errors with `@unchecked Sendable`, `nonisolated(unsafe)` or `@preconcurrency`.
- Edit `project.pbxproj` or change settings in Xcode's UI. Change `project.yml`, and only when asked.
- Add third-party dependencies without asking first.
